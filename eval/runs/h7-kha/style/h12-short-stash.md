ต่างกันที่ประวัติค่ะ stash เก็บงานไว้นอก branch ไม่มี commit โผล่ใน log ส่วน commit เก็บไว้ก่อนคือสร้างจุดในประวัติจริง ๆ ที่ push ได้

- stash: เหมาะกับงานค้างสั้น ๆ เช่น ต้องสลับไปแก้ branch อื่นด่วน แล้วค่อย `git stash pop` กลับมา เก็บเป็น stack ถ้าดองหลายอันจะงงว่าอันไหนคืออะไร เพราะไม่มีข้อความอธิบาย
- commit: เหมาะกับงานที่ทำค้างหลายวัน หรืออยาก push ขึ้น remote กันเครื่องพัง เขียนข้อความบอกตัวเองได้ ถ้าไม่อยากให้ติดไปตอน merge ก็ `git commit -m "wip"` ไว้ แล้วค่อย `git reset --soft HEAD~1` หรือ squash ทีหลัง

ส่วนตัวแนะนำ commit แบบ wip เป็นค่าเริ่มต้น เพราะ stash หายง่ายกว่าเวลา clone ใหม่หรือเปลี่ยนเครื่อง แล้วไฟล์ที่ยังไม่ track ก็ไม่ติดไปกับ stash ถ้าไม่ใส่ `-u`
