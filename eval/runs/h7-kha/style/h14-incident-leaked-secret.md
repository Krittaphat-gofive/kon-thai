รหัสผ่านตัวนั้นถือว่าหลุดไปแล้วแน่นอน สิ่งแรกที่ต้องทำคือเปลี่ยนรหัส ไม่ใช่ลบ commit ค่ะ

public repo มี bot ไล่ scan commit ใหม่ตลอดเวลา ส่วนใหญ่เจอภายในไม่กี่นาทีหลัง push ผ่านมาหนึ่งวันแปลว่าน่าจะมีคนเก็บไปแล้ว การลบ history ทีหลังไม่ได้ทำให้รหัสที่หลุดไปแล้วปลอดภัยขึ้น

**ลำดับที่ควรทำ**

1. เปลี่ยนรหัสผ่านของ DB user ตัวนั้นทันที ถ้า user นี้ใช้ร่วมกันหลายระบบ ให้เตรียม config ทุกที่ที่ใช้ให้พร้อมก่อน แล้วเปลี่ยนรวดเดียว
2. ล็อก network ก่อนถ้ายังเปลี่ยนรหัสไม่ได้เดี๋ยวนี้ เช็ก firewall rule หรือ security group ว่า DB เปิดรับ connection จาก 0.0.0.0/0 อยู่หรือเปล่า ถ้าใช่ ให้เหลือเฉพาะ IP ของ server
3. ไล่ดู connection log ย้อนหลังตั้งแต่เวลาที่ push ขึ้นไป หา IP ที่ไม่รู้จัก และดูว่ามี user ใหม่ สิทธิ์ที่เปลี่ยนไป หรือร่องรอยการอ่านข้อมูลยกชุดไหม
4. ลบ secret ออกจาก history ด้วย `git filter-repo` หรือ BFG แล้ว force push และบอกคนในทีมให้ re-clone ไม่งั้นมีคนเผลอ push commit เก่ากลับขึ้นไปได้
5. แจ้ง GitHub Support ให้ล้าง cached view เพราะ URL ของ commit sha เดิมยังเปิดดูได้อยู่แม้ force push ไปแล้ว ถ้ามีใคร fork ไว้ ต้องให้ลบ fork ด้วย
6. ย้าย connection string ไป environment variable หรือ secret manager (Key Vault, AWS Secrets Manager) แล้วใส่ไฟล์ config ไว้ใน `.gitignore`
7. scan ทั้ง repo ด้วย gitleaks หรือ trufflehog เผื่อมีอย่างอื่นหลุดไปด้วย แล้วติด pre-commit hook ไว้กันรอบหน้า

**เรื่องในองค์กร**

ถ้า database ตัวนั้นมีข้อมูลส่วนบุคคล แจ้งคนที่ดูแล security หรือ compliance ของบริษัทด้วย PDPA กำหนดให้แจ้งเหตุภายใน 72 ชั่วโมงนับจากรู้เหตุถ้าเข้าข่ายข้อมูลรั่ว ให้คนที่รับผิดชอบเป็นคนตัดสินว่าเคสนี้ต้องแจ้งหรือเปล่า จะได้ไม่ไปตัดสินใจเองคนเดียว

ใช้ database อะไรและ host ไว้ที่ไหนคะ เดี๋ยวบอกขั้นตอน rotate กับคำสั่งลบ history ให้ตรงกับของจริงกว่านี้
