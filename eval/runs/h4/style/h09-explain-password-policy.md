สองเรื่องนี้คนละสาเหตุกันครับ อันแรกเป็นนโยบายที่ตั้งไว้ตั้งใจ ส่วนอันที่สองเป็นกลไกของระบบที่ทำงานอัตโนมัติ

## ทำไมต้องเปลี่ยนรหัสผ่านทุก 90 วัน

อธิบายแบบเทียบกับของใกล้ตัว: รหัสผ่านเหมือนกุญแจบ้าน ถ้ากุญแจหายโดยไม่รู้ตัว คนที่เก็บได้ก็เข้าบ้านได้เรื่อย ๆ การบังคับเปลี่ยนทุก 90 วันคือการเปลี่ยนลูกบิดตามรอบ ถึงรหัสจะหลุดไปจริง คนที่ได้ไปก็ใช้ได้ไม่เกิน 90 วัน

ที่ต้องทำแบบนี้เพราะรหัสผ่านหลุดส่วนใหญ่ไม่มีสัญญาณเตือน ไม่มีใครมาบอกว่ารหัสคุณรั่วแล้วนะ เคสที่เจอบ่อยคือพนักงานใช้รหัสเดียวกับเว็บอื่น แล้วเว็บนั้นข้อมูลรั่ว รหัสของบริษัทเลยติดไปด้วย

อีกเหตุผลที่เจอบ่อยในองค์กรคือข้อกำหนดจากมาตรฐานหรือจากลูกค้า เช่น ISO 27001 หรือเงื่อนไขในสัญญาที่ระบุว่าต้องมีรอบเปลี่ยนรหัสผ่าน ตอน audit จะมีคนมาขอดูว่าตั้งค่าไว้จริงไหม

แต่มีอีกด้านที่ควรบอก HR ไว้ด้วย: มาตรฐานใหม่อย่าง NIST SP 800-63B แนะนำให้เลิกบังคับเปลี่ยนตามรอบแล้ว เพราะพอบังคับบ่อย คนจะตั้งเป็น Password01! แล้ว Password02! ซึ่งเดาง่ายกว่าเดิม ทิศทางตอนนี้คือเปลี่ยนเมื่อมีสัญญาณว่ารหัสหลุด แล้วไปลงแรงกับ MFA แทน ถ้า HR อยากรื้อนโยบายนี้ ก็มีข้ออ้างอิงรองรับ

ส่วนที่นี่ตั้ง 90 วันด้วยเหตุผลข้อไหน ผมตอบแทนไม่ได้ ต้องถามคนที่เป็นเจ้าของนโยบายความปลอดภัย

## ทำไมบางทีระบบเด้งออกเอง

ตรงนี้ไม่ใช่ระบบพัง แต่ออกแบบให้เป็นแบบนั้น เผื่อกรณีลืมล็อกเอาต์ทิ้งไว้บนเครื่องส่วนกลางหรือทำโน้ตบุ๊กหาย

สาเหตุที่เจอบ่อย
- ไม่ได้แตะหน้าจอนานเกินเวลาที่ตั้งไว้ ระบบตัดออกเอง (idle timeout)
- ครบอายุ session ตามรอบ ถึงจะนั่งใช้งานอยู่ก็เด้ง เช่น ตั้งไว้ 8 ชั่วโมงต่อการล็อกอินหนึ่งครั้ง
- เพิ่งเปลี่ยนรหัสผ่าน ระบบจะตัด session เก่าทุกเครื่องทิ้ง ต้องล็อกอินใหม่หมด
- ไปล็อกอินอีกเครื่อง ถ้าระบบอนุญาตให้ใช้ทีละเครื่อง เครื่องเดิมจะหลุด
- ทีมเรา deploy หรือ restart server ระหว่างวัน คนที่ค้างอยู่จะหลุดพร้อมกัน
- สลับเน็ตหรือต่อ VPN ทำให้ IP เปลี่ยน บางระบบมองว่าเป็นคนละเครื่องเลยตัดออก

ข้อสังเกตที่ช่วยแยกได้: ถ้าหลุดพร้อมกันหลายคนในเวลาเดียว มักเป็นฝั่งระบบ (deploy หรือ restart) ถ้าหลุดคนเดียวตอนลุกไปประชุม มักเป็น idle timeout

## ข้อความที่ส่งต่อให้พนักงานได้เลย

> การเปลี่ยนรหัสผ่านทุก 90 วันเป็นมาตรการลดความเสี่ยง ถ้ารหัสผ่านรั่วออกไปโดยไม่มีใครรู้ตัว การเปลี่ยนตามรอบจะจำกัดไม่ให้คนที่ได้รหัสไปใช้งานได้นาน แนะนำให้ตั้งรหัสใหม่ที่ไม่ใช่การแก้ตัวเลขท้ายจากรหัสเดิม และไม่ใช้ซ้ำกับรหัสของเว็บไซต์ส่วนตัว
>
> ส่วนกรณีที่ระบบให้ล็อกอินใหม่ระหว่างวัน เกิดได้จากการไม่ได้ใช้งานนานเกินกำหนด การล็อกอินจากอีกเครื่อง หรือช่วงที่มีการอัปเดตระบบ ไม่ใช่ความผิดปกติและไม่กระทบข้อมูลที่บันทึกไว้แล้ว หากถูกตัดออกบ่อยผิดปกติ รบกวนแจ้งทีม IT พร้อมบอกวันเวลาที่เกิด

ถ้าอยากได้ตัวเลขจริงว่าระบบเราตั้ง idle timeout กับอายุ session ไว้เท่าไหร่ บอกได้ว่าเป็นระบบตัวไหน เดี๋ยวผมไปเปิดค่า config ให้ครับ
