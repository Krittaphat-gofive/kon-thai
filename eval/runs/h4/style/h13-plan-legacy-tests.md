เริ่มจากโค้ดที่พังบ่อยและโค้ดที่แก้บ่อย ไม่ใช่ไล่เขียนตามโครงสร้างโฟลเดอร์ครับ โปรเจกต์เก่าส่วนใหญ่ที่ลงมือแบบ "เขียนให้ครบทุกไฟล์" จะเลิกกลางทางภายในสองสัปดาห์

## 1. ทำให้รัน test ได้ก่อน

สร้าง test project ให้รันด้วยคำสั่งเดียว แล้วเขียน test ง่าย ๆ ตัวเดียวให้ผ่าน จากนั้นต่อเข้า CI เลยตั้งแต่วันแรก test ที่ไม่มีใครรันก็เท่ากับไม่มี ขั้นนี้ยังไม่ต้องสนใจว่า test มีคุณค่าแค่ไหน แค่ให้ท่อมันครบ

## 2. เป้าหมายแรกคือ logic ที่ไม่แตะอะไรข้างนอก

หาฟังก์ชันที่รับค่าเข้า คำนวณ แล้วคืนค่าออก ไม่ยิง DB ไม่อ่านเวลา ไม่เรียก network เช่น คิดราคา คิดภาษี คิดส่วนลด ตัดสต็อก validate ฟอร์ม แปลงรูปแบบข้อมูล

พวกนี้เขียน test ง่ายที่สุด และมักเป็นจุดที่ผิดแล้วเจ็บที่สุดด้วย ได้ความมั่นใจเร็วโดยไม่ต้องรื้อสถาปัตยกรรม

## 3. เจอบั๊กเมื่อไหร่ เขียน test ก่อนแก้

ทุกบั๊กที่เข้ามา ให้เขียน test ที่ reproduce อาการนั้นให้ fail ก่อน แล้วค่อยแก้จนเขียว วิธีนี้ได้ test ที่มีคุณค่าแน่นอน เพราะพิสูจน์มาแล้วว่าตรงนั้นพังจริง และ test จะค่อย ๆ โตไปกองอยู่ในส่วนที่เปราะที่สุดของระบบเอง

## 4. โค้ดเก่าที่ test ไม่ได้ ให้แยก seam ออกมา

อาการที่เจอบ่อยคือ `new` service ตรง ๆ กลาง method, เรียก static, อ่าน `DateTime.Now`, ยิง query กลางฟังก์ชัน

วิธีที่เบาที่สุดคือดึงเฉพาะส่วนที่ตัดสินใจออกมาเป็น method ที่รับ input คืน output แล้ว test ตัวนั้น ส่วนที่เหลือปล่อยไว้เป็นแค่กาวเชื่อม ไม่ต้อง refactor ทั้งคลาส

ถ้าต้องแก้โค้ดก้อนที่ไม่มีใครกล้าแตะ ให้เขียน characterization test ล็อกพฤติกรรมปัจจุบันไว้ก่อน คือบันทึกว่า "ตอนนี้ใส่ค่านี้แล้วได้ค่านี้" ไม่ใช่ "ควรได้ค่านี้" แล้วค่อย refactor โดยดูว่า test ยังเขียวอยู่

## 5. ถ้า unit test แพงเกินไป ขยับขึ้นไปอีกชั้น

บางโมดูลแยก dependency ไม่ไหวจริง ๆ กรณีนี้เขียน integration test ระดับ API endpoint คุ้มกว่า ยิง request เข้าไปแล้วเช็ก response กับ state ใน DB test ตัวเดียวครอบทั้ง controller, service, repository ช้ากว่า unit test แต่ได้ safety net เร็วกว่ามาก

## 6. อย่าตั้งเป้า coverage ทั้ง repo

ตัวเลขรวมจะต่ำอยู่หลายเดือน แล้วทุกคนจะเลิกสนใจมัน ตั้งกฎที่ diff แทน: โค้ดที่เพิ่มหรือแก้ใน PR ต้องมี test คุม ส่วนของเดิมปล่อยไว้จนกว่าจะมีเหตุให้แตะ แบบนี้ coverage จะไต่ขึ้นเองตามงานที่ทำจริง

ถ้าบอก stack กับลักษณะโปรเจกต์มาด้วย เดี๋ยวช่วยเลือกจุดเริ่มกับเครื่องมือให้ตรงกว่านี้ได้ครับ
