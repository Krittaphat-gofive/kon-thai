สั้น ๆ คือแยกกันเพราะ JWT ยกเลิกกลางคันไม่ได้ครับ ถ้ามี token เดียวจะเลือกได้อย่างเดียวระหว่างปลอดภัยกับไม่ต้อง login บ่อย

## ปัญหาที่ทำให้ต้องมีสองตัว

API ตรวจ JWT จาก signature อย่างเดียว ไม่ต้องถาม DB ว่า token ใบนี้ยังใช้ได้อยู่ไหม ข้อดีคือเร็วและ scale ง่าย ข้อเสียคือออกไปแล้วเรียกคืนไม่ได้ ต้องรอหมดอายุอย่างเดียว

ทีนี้ถ้าใช้ token ใบเดียว
- ตั้งอายุ 7 วัน: user สบาย แต่ถ้า token หลุด คนขโมยใช้ได้ยาว 7 วัน กดปุ่ม logout ก็ไม่ช่วย เพราะฝั่ง server ไม่รู้จัก token ใบไหนเลย
- ตั้งอายุ 10 นาที: หลุดแล้วเสียหายน้อย แต่ user ต้อง login ใหม่ทุก 10 นาที

แยกเป็นสองใบเพื่อเอาข้อดีของทั้งสองแบบ

| | access token | refresh token |
|---|---|---|
| อายุ | 5 - 15 นาที | 7 - 30 วัน |
| ส่งไปที่ไหน | ทุก request ที่เรียก API | endpoint เดียวคือ `/auth/refresh` |
| ฝั่ง server เก็บไหม | ไม่เก็บ ตรวจ signature พอ | เก็บใน DB หรือ Redis |
| เพิกถอนได้ไหม | ไม่ได้ รอหมดอายุ | ได้ ลบออกจาก DB |
| เก็บฝั่ง client ตรงไหน | memory | httpOnly cookie |

จุดสำคัญคือ refresh token ถูกเรียกไม่บ่อย แค่ 10 - 15 นาทีครั้ง เลยแตะ DB ได้โดยไม่กระทบ performance พอแตะ DB ได้ก็เพิกถอนได้ ส่วน access token ที่โดนยิงทุก request ก็ยังเร็วเหมือนเดิมเพราะไม่ต้องคุย DB

## flow ปกติ

1. login สำเร็จ server ออกทั้งสองใบ
2. client ยิง API ด้วย access token ไปเรื่อย ๆ
3. access token หมดอายุ API ตอบ 401
4. client ยิง `/auth/refresh` พร้อม refresh token ได้ access token ใบใหม่
5. refresh token หมดอายุเมื่อไหร่ ค่อย login ใหม่

ตอน logout เราลบ refresh token ออกจาก DB ส่วน access token ใบที่ยังอยู่ในมือ client จะใช้ได้อีกไม่เกินอายุที่เหลือ ซึ่งสั้นพอที่จะยอมรับได้

## refresh token rotation

ทุกครั้งที่ refresh ให้ออก refresh token ใบใหม่แล้วทิ้งใบเก่าไปด้วย ไม่ใช่คืนแค่ access token

ที่ทำแบบนี้เพราะถ้ามีคนขโมย refresh token ไป สุดท้ายจะมีสองฝ่ายถือใบเดียวกัน พอฝ่ายหนึ่งใช้ อีกฝ่ายจะถือใบที่ใช้ไปแล้ว เรา detect ได้ว่ามีการใช้ใบเก่าซ้ำ แล้ว revoke ทั้งสายของ user คนนั้น บังคับ login ใหม่

## กับดักที่เจอบ่อย

- ทำ refresh token เป็น JWT แบบ stateless เหมือนกัน แล้วไม่เก็บลง DB แบบนี้ไม่ได้อะไรเพิ่มขึ้นมาเลย ยังเพิกถอนไม่ได้เหมือนเดิม แค่ย้ายปัญหาไปอีกใบ
- เก็บทั้งสองใบไว้ใน localStorage ถ้าเว็บมีช่อง XSS script จะอ่าน refresh token ไปได้ ซึ่งมีค่ามากกว่า access token เยอะ
- ตั้งอายุ access token เป็นชั่วโมงหรือเป็นวัน พอทำแบบนี้ refresh token ก็แทบไม่มีประโยชน์ เพราะช่วงเวลาที่ token หลุดแล้วยังใช้ได้ยังยาวอยู่ดี
- ไม่ได้กัน race condition ฝั่ง client ถ้ามี request หลายตัวเจอ 401 พร้อมกัน แล้วต่างคนต่างยิง refresh พร้อมกัน พอเปิด rotation ไว้จะมีตัวที่ถือใบเก่าแล้วโดนมองว่าเป็นการขโมย ทางแก้คือให้ refresh ได้ทีละตัว ตัวอื่นรอผลแล้ว retry ตาม
