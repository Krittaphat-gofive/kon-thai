ต่างกันที่ว่างานนั้นเข้า history ของ branch หรือไม่ค่ะ

**stash** เก็บไว้นอก branch เป็นกองกลางของ repo ไม่ผูกกับ branch ไหน

- สลับ branch ไปมาแล้วเอากลับมา apply ตรงไหนก็ได้
- push ขึ้น remote ไม่ได้ คนอื่นไม่เห็น
- ไม่มี message ที่สื่อความ ถ้ากองหลายอันจะงงว่าอันไหนคืออะไร
- pop แล้วชนกันก็ต้องแก้ conflict เอง และถ้า drop ทิ้งไปกู้ยากกว่า

**commit เก็บไว้ก่อน** (แบบ WIP) เข้า history ของ branch เลย

- มี message มี hash อยู่ใน reflog ของ branch กู้คืนง่ายกว่า
- push ขึ้นไปสำรองไว้บน remote ได้
- ไม่สวยก็แก้ทีหลังได้ด้วย `git commit --amend` หรือ `git rebase -i` ก่อน merge

เอาจริง ๆ ส่วนใหญ่ใช้ commit WIP จะปลอดภัยกว่า เก็บ stash ไว้ใช้ตอนพักงานสั้น ๆ เช่น ขอ pull ก่อนหรือต้องกระโดดไปแก้ branch อื่นแป๊บเดียว
