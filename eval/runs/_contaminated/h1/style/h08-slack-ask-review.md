ร่างให้แล้วครับ แนวคิดคือลดความกดดันด้วยการ "ชี้เป้า" ให้ชัดว่าไฟล์ไหนต้องอ่านจริง ๆ เพราะสิ่งที่ทำให้คน review อึดอัดไม่ใช่จำนวนไฟล์ แต่คือการไม่รู้ว่าต้องอ่านทั้งหมดไหม

**ข้อความสำหรับ Slack**

> ขอแรงช่วย review PR หน่อยครับ 🙏
>
> 🔗 [ลิงก์ PR]
> ทำอะไร: [สรุปสั้น ๆ 1-2 บรรทัด]
>
> ไฟล์เยอะหน่อยประมาณ 40 ไฟล์ แต่ส่วนใหญ่เป็น [rename / ย้าย folder / generated code] ที่ไถผ่านได้เร็ว ๆ จุดที่อยากให้ช่วยดูจริง ๆ มีแค่ 3 ไฟล์
>
> • `src/xxx.ts` logic หลักอยู่ตรงนี้
> • `src/yyy.ts` ตรงนี้เปลี่ยนวิธี handle error อยากฟังความเห็น
> • `src/zzz.ts` เพิ่ม migration ช่วยเช็กว่า rollback ได้จริง
>
> ดูแค่ 3 ไฟล์นี้ก็พอครับ น่าจะประมาณ 15-20 นาที comment ทิ้งไว้ได้เลย ไม่ต้องรีบ สะดวกช่วงไหนของสัปดาห์นี้ก็ได้ ใครอยากให้เล่าภาพรวมก่อนบอกได้ เดี๋ยวนัดคุย 10 นาที

**ทำไมถึงเขียนแบบนี้**

- บอกตรง ๆ ว่า 40 ไฟล์ แต่ตามด้วยเหตุผลทันที คนอ่านจะได้ไม่ตกใจแล้วเลื่อนผ่าน
- ให้ตัวเลขเวลา (15-20 นาที) คนจะกะได้ว่าแทรกตรงไหนของวันได้บ้าง
- ไม่ระบุ deadline เป็นวัน ใช้ "สัปดาห์นี้" กว้าง ๆ แทน
- "ดูแค่ 3 ไฟล์นี้ก็พอ" คือประโยคสำคัญที่สุด เป็นการบอกว่าไม่ต้องรับผิดชอบทั้ง PR
- ปิดด้วยการเสนอเล่าให้ฟัง แทนที่จะปล่อยให้คน review ไปงมเอง

**ถ้าอยากได้สั้นกว่านี้**

> ขอคน review PR นี้หน่อยครับ [ลิงก์] ไฟล์ 40 แต่จุดสำคัญอยู่ที่ `xxx.ts` กับ `yyy.ts` เท่านั้น ที่เหลือเป็น rename ล้วน ๆ ดูสองไฟล์นี้ก็พอ ไม่ต้องรีบครับ

ถ้าบอกมาว่า PR นี้ทำอะไรและไฟล์ไหนคือหัวใจ เดี๋ยวผมเติมรายละเอียดให้ตรงงานจริงเลยครับ
