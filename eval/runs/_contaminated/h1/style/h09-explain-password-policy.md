สองเรื่องนี้คนละเรื่องกันครับ การเปลี่ยนรหัสทุก 90 วันมาจากนโยบายความปลอดภัยที่ตั้งไว้ ส่วนการเด้งออกเองคือ "บัตรผ่าน" ที่ระบบออกให้ตอน login หมดอายุ ไม่ใช่ระบบพัง

## ทำไมต้องเปลี่ยนรหัสทุก 90 วัน

เทียบง่าย ๆ รหัสผ่านก็เหมือนกุญแจบ้าน ปัญหาของกุญแจคือหายแล้วเจ้าของไม่รู้ตัว ใครเก็บไปได้ก็เข้าบ้านได้เรื่อย ๆ จนกว่าจะเปลี่ยนลูกบิด การบังคับเปลี่ยนทุก 90 วันก็คือเปลี่ยนลูกบิดตามรอบ เผื่อกุญแจหลุดไปแล้วไม่มีใครรู้ อย่างน้อยคนที่ได้ไปก็ใช้ได้ไม่เกิน 90 วัน

ตัวเลข 90 วันปกติมาจากสามทาง
- มาตรฐานที่บริษัทต้องผ่าน เช่น ISO 27001 หรือข้อกำหนดจากลูกค้าองค์กร
- นโยบายที่ฝั่ง IT ตั้งไว้ตามแนวปฏิบัติเดิม
- ค่า default ของระบบเอง เช่น Windows Active Directory ตั้งมา 90 วันตั้งแต่แรก

มีอีกประเด็นที่น่าจะมีประโยชน์ถ้า HR จะทบทวนนโยบาย คือมาตรฐานสากลตอนนี้ (NIST SP 800-63B) เลิกแนะนำการบังคับเปลี่ยนตามรอบแล้ว เหตุผลคือพอบังคับบ่อย ๆ คนจะตั้ง `Password01` แล้วเปลี่ยนเป็น `Password02` หรือไม่ก็จดแปะไว้ข้างจอ กลายเป็นเสี่ยงกว่าเดิม แนวทางใหม่คือให้ตั้งรหัสยาว ๆ ไปเลยแล้วไม่ต้องเปลี่ยนตามรอบ บังคับเปลี่ยนเฉพาะตอนมีสัญญาณว่ารหัสหลุด แล้วเปิด MFA (ยืนยันตัวตนสองชั้น) มาช่วยแทน

ถ้าจะเปลี่ยนนโยบายจริง ต้องเช็กก่อนว่า 90 วันมาจากข้อบังคับที่เลี่ยงไม่ได้หรือเปล่า

## ทำไมบางทีระบบเด้งออกเอง

ตอน login ระบบจะออกบัตรผ่านชั่วคราวให้ใบหนึ่ง (เรียกว่า session) บัตรใบนี้มีวันหมดอายุของตัวเอง พอหมดก็ต้อง login ใหม่ สาเหตุที่เจอบ่อย

1. ไม่ได้แตะหน้าจอนานเกินกำหนด เช่น ปล่อยค้างไว้ 30 นาทีแล้วไปประชุม
2. ครบอายุสูงสุดของ session เช่น 8 ชั่วโมง ต่อให้นั่งทำงานอยู่ตลอดก็ต้อง login ใหม่
3. เพิ่งเปลี่ยนรหัสผ่าน หรือ IT แก้สิทธิ์ให้ ระบบจะยกเลิก session เก่าทั้งหมดทันที (ข้อนี้คือจุดที่สองคำถามมาเจอกัน พอถึงรอบ 90 วันแล้วเปลี่ยนรหัส คนมักจะเจอเด้งออกพร้อมกันหลายคน)
4. login ซ้ำจากอีกเครื่อง ถ้าระบบอนุญาตแค่เครื่องเดียว เครื่องแรกจะหลุด
5. เน็ตสะดุดหรือสลับจาก wifi ไป 4G
6. ทีมพัฒนา deploy เวอร์ชันใหม่ บางระบบที่เก็บ session ไว้ในหน่วยความจำจะหลุดยกชุด

ข้อ 1-4 คือตั้งใจออกแบบให้เป็นแบบนั้น ส่วนข้อ 5-6 เป็นผลข้างเคียง ถ้าพนักงานเจอถี่ผิดปกติ เช่น วันละหลายรอบทั้งที่นั่งใช้งานอยู่ อันนี้ไม่ปกติ ควรให้ IT ไปดู log

## ประโยคที่เอาไปตอบพนักงานได้เลย

> ระบบกำหนดให้เปลี่ยนรหัสผ่านทุก 90 วันตามนโยบายความปลอดภัยของบริษัท เพื่อจำกัดความเสียหายกรณีที่รหัสผ่านหลุดออกไปโดยเจ้าของไม่รู้ตัว
>
> ส่วนกรณีที่ระบบให้ login ใหม่เอง เกิดจากการที่ไม่ได้ใช้งานต่อเนื่องนานเกินกำหนด หรือครบอายุการใช้งานของรอบนั้น ถือเป็นการทำงานปกติของระบบ แต่ถ้าพบว่าเกิดบ่อยผิดปกติระหว่างใช้งานอยู่ รบกวนแจ้ง IT พร้อมระบุเวลาที่เกิดเหตุ

## ถ้าอยากลดเสียงบ่น

- เปิด MFA แล้วยืดรอบเปลี่ยนรหัสออกไป เป็นทางที่ปลอดภัยขึ้นและคนบ่นน้อยลง
- ทำ SSO ให้ login ครั้งเดียวใช้ได้หลายระบบ
- เปิดฟีเจอร์ "จำเครื่องนี้ไว้ 30 วัน" สำหรับเครื่องของบริษัท
- ยืดเวลา idle timeout เฉพาะระบบที่ไม่ได้เก็บข้อมูลอ่อนไหว

บอกได้ไหมครับว่าเป็นระบบตัวไหน (AD, HR system, หรือ web app ที่ทีมเราทำเอง) เดี๋ยวผมดูค่าที่ตั้งไว้จริงให้ แล้วบอกได้ว่าปรับตรงไหนได้บ้างครับ
