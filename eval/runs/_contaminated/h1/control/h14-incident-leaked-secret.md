สรุปก่อนเลย: ให้ถือว่ารหัสผ่านนั้นหลุดไปแล้วแน่นอน สิ่งแรกที่ต้องทำคือเปลี่ยนรหัส ไม่ใช่ลบ commit เพราะการล้างประวัติทีหลังไม่ช่วยอะไรถ้ารหัสเดิมยังใช้ได้อยู่ครับ

เหตุผลคือมี bot กวาด public repo หา secret ตลอดเวลา ส่วนใหญ่เจอภายในไม่กี่นาทีหลัง push ผ่านไปหนึ่งวันถือว่านานมากแล้ว

## 1. เปลี่ยนรหัสผ่าน database ทันที

- สร้าง user ใหม่พร้อมรหัสใหม่ แล้ว revoke หรือลบ user เดิมทิ้ง ดีกว่าแค่เปลี่ยนรหัสให้ user เดิม
- ก่อนเปลี่ยน ไล่ให้ครบก่อนว่ามี service ตัวไหนใช้ user นี้บ้าง จะได้อัปเดต connection string พร้อมกัน ไม่ให้ระบบล่ม
- ถ้ารหัสนี้ไปใช้ซ้ำที่ระบบอื่น เปลี่ยนทุกที่ด้วย

## 2. ปิดทางเข้าไว้ก่อน

connection string บอก hostname กับ port ไปด้วย คนที่เก็บไปแล้วรู้หมดว่า database อยู่ตรงไหน

- เช็กว่า database เปิดรับ connection จาก public internet หรือเปล่า ถ้าเปิดอยู่ ให้จำกัดเป็น IP allowlist, VPC หรือ private endpoint
- ถ้าทำได้เร็ว ตั้ง firewall rule ให้รับเฉพาะ IP ของ app server ระหว่างที่ยังเปลี่ยนรหัสไม่เสร็จ

## 3. ไล่ดู log ว่ามีใครเข้ามาแล้วหรือยัง

ดูช่วงตั้งแต่เวลาที่ push เมื่อวานถึงตอนนี้

- login log กับ audit log ของ database หา IP ที่ไม่ใช่ของ server เรา
- connection ที่เข้ามาผิดเวลา หรือ query ที่ดึงข้อมูลทีละเยอะผิดปกติ
- เช็กว่ามีการสร้าง user ใหม่ เปลี่ยน permission ทิ้งตาราง หรือข้อมูลหายไปไหม
- ถ้าเป็น cloud database อย่าง Azure SQL, RDS หรือ MongoDB Atlas พวกนี้มี audit log ให้อยู่แล้ว เปิดดูได้เลย

ข้อนี้สำคัญ เพราะผลที่ได้จะตัดสินว่าเรื่องนี้จบที่ "เปลี่ยนรหัสแล้วจบ" หรือกลายเป็น data breach ที่ต้องรายงาน

## 4. ล้างประวัติใน git

ทำทีหลังได้ ไม่ต้องรีบเท่าสามข้อบน

- ถ้า repo ยังใหม่และไม่มีคนอื่นใช้มาก วิธีเร็วที่สุดคือลบ repo ทิ้งแล้วสร้างใหม่ push เฉพาะโค้ดที่สะอาด
- ถ้าต้องเก็บประวัติไว้ ใช้ `git filter-repo` (แนะนำกว่า `filter-branch`) สร้างไฟล์ `secrets.txt` ใส่บรรทัด `รหัสผ่านจริง==>REMOVED` แล้วรัน `git filter-repo --replace-text secrets.txt` ตามด้วย `git push --force --all` และ `--tags`
- git จะสร้าง commit SHA ใหม่หมด คนในทีมต้อง clone ใหม่ ห้าม merge branch เก่าที่ยังค้างอยู่เครื่องกลับเข้ามา ไม่งั้นรหัสเด้งกลับมาใหม่

## 5. GitHub cache กับ fork

ข้อนี้คนมักมองข้าม

- ต่อให้ force push ไปแล้ว commit เก่ายังเปิดดูได้ผ่าน URL ตรง ๆ อีกพักใหญ่ เพราะ GitHub เก็บ cache ไว้ ต้องเปิด ticket หา GitHub Support ให้ garbage collect ให้
- ถ้ามีคน fork ไปแล้ว fork นั้นยังมีรหัสอยู่ เราล้างเองไม่ได้ ต้องให้ GitHub จัดการ

ย้ำอีกทีว่าข้อ 4 กับ 5 เป็นแค่การเก็บกวาด ตัวที่แก้ปัญหาจริงคือข้อ 1

## 6. กันไม่ให้เกิดซ้ำ

- ย้าย secret ออกจาก repo ไปไว้ใน `.env` หรือ `appsettings.Development.json` แล้วใส่ `.gitignore` commit แค่ `.env.example` ที่มีเฉพาะชื่อ key
- production ใช้ secret manager เช่น Azure Key Vault, AWS Secrets Manager หรือ GitHub Actions secrets อย่าฝังในไฟล์
- เปิด secret scanning กับ push protection ใน repo setting ของ GitHub ฟรีสำหรับ public repo และ GitHub จะบล็อกตั้งแต่ตอน push
- ลง gitleaks หรือ trufflehog เป็น pre-commit hook กับ CI step อีกชั้น

## 7. เรื่องที่ต้องรายงาน

ถ้า database นี้มีข้อมูลส่วนบุคคล ให้แจ้งหัวหน้ากับทีม security ตั้งแต่ตอนนี้ อย่าเก็บไว้คนเดียว

ตาม PDPA ถ้ามีเหตุให้เชื่อว่ามีคนเข้าถึงข้อมูลจริงและเสี่ยงกระทบสิทธิเจ้าของข้อมูล องค์กรต้องแจ้งสำนักงาน PDPC ภายใน 72 ชั่วโมงนับจากที่ทราบเหตุ ตรงนี้ไม่ใช่การตัดสินใจของ dev คนเดียว ให้ทีมที่รับผิดชอบเป็นคนชี้ขาด
