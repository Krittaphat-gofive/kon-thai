อธิบายได้ประมาณนี้ครับ ขอแยกเป็นสองเรื่องก่อน เพราะคนละสาเหตุกัน แต่พนักงานมักเหมารวมว่าเป็นเรื่องเดียวกัน

## 1. ทำไมบังคับเปลี่ยนรหัสผ่านทุก 90 วัน

เปรียบเทียบแบบที่ HR เล่าต่อได้ง่าย ๆ รหัสผ่านก็เหมือนกุญแจห้อง ปัญหาของกุญแจคือถ้าทำหล่นแล้วมีคนเก็บไป เราจะไม่รู้เลยว่าหล่น และคนที่เก็บได้ก็เข้าห้องได้เรื่อย ๆ ไม่มีวันหมดอายุ

การบังคับเปลี่ยนทุก 90 วัน คือการเปลี่ยนลูกบิดตามรอบ ไม่ได้แปลว่าสงสัยพนักงานคนไหน แต่เป็นการจำกัดความเสียหายว่า ถ้ากุญแจหลุดไปจริง คนที่ได้ไปจะใช้ได้นานที่สุด 90 วัน ไม่ใช่ตลอดชีพ

เหตุผลที่องค์กรส่วนใหญ่ตั้งรอบนี้ไว้
- รหัสผ่านหลุดส่วนใหญ่เจ้าตัวไม่รู้ตัว เช่น ไปใช้รหัสเดียวกับเว็บอื่นแล้วเว็บนั้นโดนแฮ็ก กดลิงก์ฟิชชิง หรือเครื่องติดมัลแวร์
- เป็นข้อกำหนดของมาตรฐานที่บริษัทต้องผ่าน audit เช่น ISO 27001 หรือเงื่อนไขที่ลูกค้าองค์กรบังคับมาในสัญญา
- ช่วยให้เจอบัญชีตกค้าง คนที่ลาออกหรือย้ายทีมแล้วแต่บัญชียังเปิดอยู่ พอถึงรอบเปลี่ยนรหัสแล้วไม่มีใครเปลี่ยน ก็รู้ว่าบัญชีนี้ไม่มีคนใช้

## 2. ทำไมระบบเด้งออกเอง

อันนี้คนละเรื่องกับ 90 วัน และไม่ได้แปลว่าระบบมีปัญหา สาเหตุที่เจอบ่อยเรียงตามความถี่

| อาการที่พนักงานเจอ | สาเหตุจริง |
|---|---|
| ไม่ได้แตะเครื่องไปสักพัก กลับมาต้อง login ใหม่ | idle timeout ระบบนับว่าไม่มีการใช้งานเกินเวลาที่ตั้งไว้ ป้องกันกรณีลืมล็อกหน้าจอแล้วลุกไปประชุม |
| ใช้งานอยู่ดี ๆ ตอนบ่าย แล้วเด้งออก | session มีอายุสูงสุดของตัวเอง พอครบเวลาก็หมดอายุ ถึงจะนั่งใช้อยู่ก็ตาม |
| เพิ่งเปลี่ยนรหัสผ่านเสร็จ แล้วเด้งออกทุกเครื่อง | ตั้งใจให้เป็นแบบนั้น พอเปลี่ยนรหัส ระบบจะตัดการ login เก่าทั้งหมด เผื่อกรณีที่เปลี่ยนรหัสเพราะสงสัยว่าโดนขโมย |
| login ที่คอมแล้วมือถือเด้งออก | บางระบบอนุญาตให้ login ได้ทีละเครื่อง |
| เด้งออกตอนเดินออกจากออฟฟิศ หรือสลับ wifi เป็น 4G | เครือข่ายเปลี่ยน ระบบมองว่าเป็นคนละการเชื่อมต่อ |
| ทั้งบริษัทเด้งออกพร้อมกันช่วงเวลาเดียว | ทีมเพิ่งอัปเดตระบบเวอร์ชันใหม่ ตอน restart เซิร์ฟเวอร์ session เดิมจะหายไป |

ประโยคสรุปที่ HR เอาไปใช้ตอบพนักงานได้เลย: "ระบบเด้งออกไม่ใช่ระบบพัง แต่เป็นการล็อกประตูอัตโนมัติเมื่อไม่มีคนใช้ หรือเมื่อมีอะไรเปลี่ยน ถ้า login กลับเข้าไปแล้วใช้งานต่อได้ตามปกติ แปลว่าไม่มีปัญหา ที่ต้องแจ้ง IT คือกรณีที่เด้งออกถี่มากจนทำงานไม่ได้ หรือ login กลับเข้าไปไม่ได้"

## หมายเหตุสำหรับฝั่งเรา ไม่ต้องบอก HR ก็ได้

เรื่องรอบ 90 วันนี่ ถ้า HR ถามต่อว่า "แล้วจะลดความรำคาญได้ไหม" มีประเด็นที่ควรรู้คือมาตรฐานสมัยใหม่อย่าง NIST SP 800-63B เลิกแนะนำการบังคับเปลี่ยนรหัสตามรอบไปแล้ว เหตุผลคือพอบังคับบ่อย คนจะตั้งรหัสที่เดาง่ายขึ้นและวนซ้ำแบบ Password01 Password02 ซึ่งปลอดภัยน้อยกว่าเดิม แนวทางที่แนะนำตอนนี้คือใช้รหัสยาว ๆ เปลี่ยนเฉพาะตอนมีเหตุว่าหลุด แล้วเปิด MFA แทน

แต่ถ้ารอบ 90 วันของเรามาจากข้อกำหนด audit หรือสัญญาลูกค้า ก็เปลี่ยนเองไม่ได้ ต้องไปแก้ที่ต้นทางก่อน เลยอยากแนะนำว่าก่อนตอบ HR ว่าจะปรับได้หรือไม่ได้ ลองเช็กก่อนว่านโยบายนี้ตั้งมาจากไหน

อีกเรื่องคือตัวเลข timeout ที่ผมยกมาในตารางเป็นสาเหตุทั่วไปของระบบส่วนใหญ่ ผมยังไม่เห็น config จริงของระบบเรา ถ้าอยากได้ตัวเลขที่แม่น เช่น idle timeout กี่นาที session อยู่ได้กี่ชั่วโมง ต้องไปเปิดดูค่าที่ตั้งไว้จริงก่อน

ถ้าอยากได้เป็นข้อความสำเร็จรูปให้ HR ประกาศลง intranet หรือตอบในไลน์กลุ่ม บอกมาได้ เดี๋ยวผมร่างให้ในโทนที่พนักงานทั่วไปอ่านแล้วเข้าใจครับ
