**stash** = เก็บงานค้างไว้ชั่วคราว ไม่ลงประวัติ
- งานหลุดออกจาก working tree ไปกองไว้ใน stack แยก
- ไม่ผูกกับ branch ไหน เอากลับมาด้วย `git stash pop` ได้ทุกที่
- ไม่มี message ชัดเจน ดอง ๆ ไว้หลายอันแล้วจะงงว่าอันไหนคืออะไร
- เหมาะกับ "ขอสลับ branch แป๊บนึง" หรือ "ต้องรีบไปแก้ bug ด่วน"

**commit เก็บไว้ก่อน (WIP commit)** = บันทึกลงประวัติจริง
- ผูกกับ branch นั้น ๆ มี hash มี message
- ปลอดภัยกว่า เพราะ push ขึ้น remote ได้ ไม่หายถ้าเครื่องพัง
- ตามหาย้อนหลังง่าย `git log` เห็นหมด
- เสร็จแล้วค่อย `git commit --amend` หรือ `git rebase -i` เกลาให้สวยก่อน merge

**เลือกยังไง**
- ค้างแค่ไม่กี่นาที แล้วกลับมาทำต่อเลย → stash
- ค้างข้ามวัน ข้ามเครื่อง หรือกลัวหาย → commit ไปเลย แล้วค่อยจัดระเบียบทีหลัง

ส่วนตัวแนะนำ commit เป็นหลัก เพราะ stash มันเงียบเกินไป ลืมง่าย แล้วเวลา `git stash drop` ผิดอันนี่คือหายจริง ๆ
