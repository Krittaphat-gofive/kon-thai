อาการ "ต้องกด refresh แรง ๆ ถึงหาย" บอกแทบจะชัดเจนแล้วว่าเป็นปัญหา **cache** ไม่ใช่โค้ดบนเซิร์ฟเวอร์ผิด เพราะ hard refresh (Ctrl+Shift+R) มันบังคับยิง `Cache-Control: no-cache` ข้าม disk cache ของเบราว์เซอร์ไปดึงของใหม่ ถ้าทำแล้วหาย แปลว่าของใหม่อยู่บนเซิร์ฟเวอร์เรียบร้อย แต่มีชั้นไหนสักชั้นระหว่างทางยังจ่ายของเก่าอยู่

## ต้นเหตุที่เจอบ่อย เรียงตามความน่าจะเป็น

**1. `index.html` โดน cache ไว้** — อันนี้คือตัวการอันดับหนึ่งของ SPA ถึงไฟล์ JS/CSS จะมี hash ใหม่แล้ว แต่ถ้าเบราว์เซอร์ยังอ่าน `index.html` ตัวเก่าจาก cache มันก็จะชี้ไปหา bundle เก่าอยู่ดี มักเกิดเวลาไม่ได้ตั้ง `Cache-Control` ให้ HTML แล้วเบราว์เซอร์เดาเอาเอง (heuristic caching ประมาณ 10% ของอายุไฟล์)

**2. ไฟล์ static ไม่มี hash ในชื่อ** — ถ้า build ออกมาเป็น `main.js`, `styles.css` เฉย ๆ ชื่อเดิมทุกรอบ เบราว์เซอร์ไม่มีทางรู้ว่าของเปลี่ยน ก็หยิบของเก่าในเครื่องมาใช้

**3. CDN / reverse proxy ยัง cache อยู่** — Cloudflare, CloudFront, nginx พวกนี้มี TTL ของตัวเอง ถ้า deploy แล้วไม่ purge ก็จะจ่ายของเก่าจนกว่าจะหมดอายุ อาการเด่นคือ *บางคน* เห็นของใหม่ *บางคน* เห็นของเก่า เพราะคนละ edge node

**4. Service Worker (ถ้าทำเป็น PWA)** — ตัวนี้ร้ายสุด เพราะมันขวางหน้า network ไว้เลย ต่อให้ล้าง cache เบราว์เซอร์ก็ไม่หาย SW ตัวใหม่จะอยู่สถานะ waiting จนกว่าแท็บเดิมจะปิดหมดทุกแท็บ

**5. Rolling deploy ยังไม่จบ** — ถ้าหลัง LB มีหลาย instance แล้วไล่อัปเดตทีละตัว ช่วงนั้นคนที่ถูกสุ่มไป pod เก่าก็จะเห็นของเก่า แต่อันนี้ปกติหายเองใน 1-2 นาที ถ้าค้างนานกว่านั้นให้ตัดทิ้งไปก่อน

## ไล่หาว่าเป็นตัวไหน

เปิด DevTools → แท็บ Network แล้ว **อย่า**ติ๊ก Disable cache (ไม่งั้นจะ reproduce ไม่เจอ) จากนั้นดู response header ของ `index.html`:

- `cache-control` / `expires` — ดูว่าใครสั่ง cache และนานแค่ไหน
- `age` — ถ้ามีค่าสูง ๆ แปลว่าโดน CDN cache ไว้
- `x-cache: HIT` หรือ `cf-cache-status: HIT` — ยืนยันว่า CDN จ่ายของเก่า
- คอลัมน์ Size ขึ้นว่า `(disk cache)` / `(memory cache)` — แปลว่าไม่ได้ออกไปถึงเซิร์ฟเวอร์เลย

แล้วเช็กแท็บ Application → Service Workers ว่ามีตัวไหน register ค้างอยู่ไหม

## วิธีแก้

หลักการคือแยก policy ของ HTML กับ asset ออกจากกันให้ชัด

| ไฟล์ | Cache-Control |
|---|---|
| `index.html` | `no-cache, must-revalidate` |
| asset ที่มี hash ในชื่อ (`main.a1b2c3.js`) | `public, max-age=31536000, immutable` |

`no-cache` ไม่ได้แปลว่าห้าม cache นะ มันแปลว่า "cache ได้ แต่ต้องถาม server ก่อนใช้ทุกครั้ง" ซึ่งถ้าไฟล์ไม่เปลี่ยนก็ได้ 304 กลับมา เบา ๆ ไม่เปลืองอะไร ส่วน asset ที่มี hash จะ cache ยาวแค่ไหนก็ได้ เพราะพอเนื้อหาเปลี่ยน ชื่อไฟล์ก็เปลี่ยนตาม

เพิ่มเติม:
- ใส่ **purge CDN** เข้าไปใน pipeline หลัง deploy เสร็จ ทำเป็นขั้นตอนอัตโนมัติไปเลย อย่าหวังว่าจะมีคนจำ
- ถ้ามี Service Worker ให้ใช้ `skipWaiting()` + `clientsClaim()` แล้วเด้ง toast บอกผู้ใช้ว่า "มีเวอร์ชันใหม่ กดเพื่อโหลดใหม่" จะคุมประสบการณ์ได้ดีกว่าปล่อยให้อัปเดตเงียบ ๆ
- ทำ endpoint `/version.json` (ตั้ง no-cache) ให้ frontend poll เทียบกับเวอร์ชันที่ถืออยู่ ถ้าไม่ตรงก็แจ้งผู้ใช้ให้รีโหลด วิธีนี้ครอบคลุมเคสคนที่เปิดแท็บค้างไว้ทั้งวันด้วย

ถ้าอยากให้ช่วยดูเฉพาะเจาะจง บอก stack กับ config ที่ใช้อยู่ (nginx conf, CDN เจ้าไหน, build tool อะไร) ได้เลย จะได้ชี้จุดได้ตรงกว่านี้
